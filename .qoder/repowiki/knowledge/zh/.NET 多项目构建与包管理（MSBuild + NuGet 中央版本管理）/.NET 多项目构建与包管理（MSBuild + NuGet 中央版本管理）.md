## 构建系统与工具链

本项目基于 **.NET 10.0** 和 **MSBuild** 构建系统，采用 .NET SDK 工作流进行编译、打包与发布。核心构建配置集中在 `src/` 目录下的共享属性文件中，通过 `.slnx` 解决方案文件统一管理所有子项目。

### 核心构建文件
- **`global.json`** — 锁定 .NET SDK 版本为 `10.0.0`，启用 `latestFeature` 前向兼容
- **`common.props`** — 全局 MSBuild 属性：目标框架 `net10.0`、隐式 using、nullable 启用、版本号 `0.7.0`
- **`Directory.Packages.props`** — 启用中央包版本管理（Central Package Management），统一声明所有依赖版本
- **`AppLab.slnx`** — 现代 .NET 解决方案文件，按业务域组织 50+ 个项目引用
- **`nuget.pack.props`** — 自定义打包目标，支持本地复制和 CI 自动推送 NuGet 包

### 包管理与依赖策略
- 使用 **NuGet Central Package Management** 集中管理所有第三方包版本，包括 ABP Framework 10.5.0、Entity Framework Core 10.0.10、Blazor 组件等
- 每个 `.csproj` 文件不直接指定包版本，仅引用包名，版本由 `Directory.Packages.props` 统一管理
- 支持开发环境本地包缓存（`NUGET_LOCAL_PATH` 环境变量）和 CI 环境自动推送（`NUGET_PUSH=true`）

### 项目结构与构建模式
项目采用 **分层架构 + 模块化设计**，每个业务域包含标准的项目结构：
- `*.Application` — 应用服务层
- `*.Application.Contracts` — DTO 和接口定义
- `*.Domain` — 领域模型
- `*.EntityFrameworkCore` — 数据访问层
- `*.Web` — Web API 或 Blazor Server 端点
- `*.Client` — Blazor WebAssembly 客户端

### 数据库迁移与部署工具
- 每个服务都有独立的 **DbMigrator** 控制台应用（位于 `Tools/` 目录）
- 使用 EF Core Migrations 进行数据库版本管理
- 提供种子数据和初始化脚本

### 容器化与编排
- 使用 **Docker Compose** 进行本地开发环境编排（`cd/docker-compose.yml`）
- 当前包含 Redis 和 RabbitMQ 依赖服务
- 尚未发现 Dockerfile，容器化可能通过其他方式实现

### 构建约定与最佳实践
1. **版本管理**：所有项目共享 `common.props` 中的版本号，确保一致性
2. **包版本控制**：禁止在项目中硬编码包版本，必须通过中央配置文件管理
3. **目标框架**：统一使用 `net10.0`，避免框架碎片化
4. **代码质量**：启用 nullable 引用类型和隐式 using，提升代码安全性
5. **模块化构建**：通过 slnx 文件精确控制项目依赖关系，支持增量构建

### 缺失的构建能力
- 未发现 CI/CD 流水线配置（如 GitHub Actions、Azure DevOps）
- 没有专门的构建脚本（Makefile、build.sh 等）
- 缺少单元测试和项目测试的配置
- 未实现跨平台编译配置
