## 1. 使用的系统与工具
- **包管理器**: NuGet（.NET 生态标准）
- **中央包版本管理**: 使用 `Directory.Packages.props` 配合 `<ManagePackageVersionsCentrally>true</ManagePackageVersionsCentrally>`，实现跨项目统一版本控制
- **SDK 锁定**: `global.json` 固定 .NET SDK 版本为 `10.0.0`，并启用 `latestFeature` 滚动策略
- **NuGet 源配置**: `NuGet.config` 仅保留官方 `nuget.org` 源，无私有源或镜像
- **解决方案文件**: `AppLab.slnx`（新版 .NET 解决方案格式）集中声明所有项目路径

## 2. 核心文件与位置
- `src/Directory.Packages.props` — 全仓库统一的 NuGet 包版本定义，按类别分组（Microsoft、ABP、Avalonia、第三方库等）
- `src/common.props` — 全局 MSBuild 属性：目标框架 `net10.0`、语言版本 `preview`、Nullable 启用、版本号 `0.7.0`
- `src/nuget.pack.props` — 打包增强：支持本地复制包（`NUGET_LOCAL_PATH`）和 CI 自动推送（`NUGET_PUSH=true` + `NUGET_API_KEY`）
- `src/NuGet.config` — 仅配置 nuget.org 源
- `src/global.json` — 锁定 .NET SDK 10.0.0
- `src/AppLab.slnx` — 解决方案级项目清单，包含 50+ 个 .csproj 项目

## 3. 架构与约定
- **中央版本管理**：所有 `.csproj` 不再内联 `<PackageReference Version="..." />`，而是通过 `Directory.Packages.props` 统一管理，避免版本碎片化
- **分层依赖结构**：包按用途分组注释（官方 Microsoft、ABP 框架、Avalonia 桌面、Elsa/Hangfire/CAP 工作流与消息队列、Serilog 日志等），便于维护
- **多目标框架**：当前统一使用 `net10.0`，但 ABP 相关包存在 `10.5.0` 与 `10.3.0` 混用情况（如 `Volo.Abp.Identity.Web` 与 `Volo.Abp.PermissionManagement.Domain.Identity`）
- **包发布流程**：通过 `nuget.pack.props` 的 MSBuild Target 实现：
  - 开发环境：设置 `NUGET_LOCAL_PATH` 环境变量，构建后自动复制 nupkg 到本地目录
  - CI 环境：设置 `NUGET_PUSH=true` 和 `NUGET_API_KEY`，构建后自动推送到 nuget.org
- **无私有 NuGet 源**：`NuGet.config` 中未配置企业私有源，所有依赖均来自 nuget.org

## 4. 开发者应遵循的规则
- **新增依赖时**：在 `Directory.Packages.props` 中添加 `<PackageVersion Include="..." Version="..." />`，而非在各项目中直接指定版本
- **更新依赖时**：修改 `Directory.Packages.props` 中的版本号，确保全仓库一致
- **不要** 在 `.csproj` 文件中硬编码包版本，应依赖中央版本管理
- **包分类维护**：新增包时应按现有注释分组（官方/ABP/Avalonia/第三方）归类
- **CI 推送规范**：推送包时需设置 `NUGET_PUSH=true` 和 `NUGET_API_KEY` 环境变量
- **SDK 升级**：如需升级 .NET SDK，需同步更新 `global.json` 中的版本
- **注意版本一致性**：当前存在 ABP 包版本不一致的情况（10.5.0 vs 10.3.0），建议逐步统一
