## 引言
本指南面向 AppLab 新加入的开发者，目标是帮助你在本地快速搭建 .NET 10 + Blazor 开发环境，理解项目的模块化架构、包管理机制、调试方式、新功能开发流程以及发布和版本管理策略。AppLab 是基于 .NET 与 Blazor 的实验性应用平台，采用模块化架构，既支持单体部署，也支持按服务独立部署；同时提供低代码设计引擎与渲染引擎、多领域服务、Avalonia 桌面宿主等能力。

## 项目结构

## 核心组件
- Web 宿主：基于 ASP.NET Core Web，聚合多个 Application 层模块，并提供 Blazor Server/WebAssembly 混合运行能力。
- WebAssembly 客户端：负责前端路由、懒加载各模块程序集、通过动态代理调用后端 IAppService。
- 桌面宿主：基于 Avalonia 的统一外壳，接入 Workbench 等客户端应用。
- 低代码层：包含元数据 Schema、组件基类、默认组件库、设计引擎与渲染引擎。
- 领域服务：按限界上下文划分，遵循 Application.Contracts/Application/EntityFrameworkCore/Web 分层。
- 迁移工具：每个服务对应一个控制台 DbMigrator，用于创建和更新数据库结构。
- 工具库：HTTP 动态代理、Blazor 工具、ID 生成器、基础类型扩展等。

## 架构总览
AppLab 的整体架构由“宿主 + 前端客户端 + 低代码层 + 领域服务 + 工具与基础设施”构成。Web 宿主作为聚合入口，注册并暴露各服务；WebAssembly 客户端按需加载模块程序集并通过 HttpClientProxy 调用后端接口；桌面宿主以 Avalonia 形式承载客户端应用；低代码层提供可视化设计与运行时渲染能力；迁移工具保证数据库结构与领域模型同步。

### 包管理机制
本项目采用集中式包版本管理，所有第三方包版本集中在 Directory.Packages.props 中定义，csproj 中仅引用包名而不写版本号；NuGet 源由 NuGet.config 指定；公共编译属性由 common.props 统一管理。

关键点：
- Directory.Packages.props：启用 ManagePackageVersionsCentrally，并集中维护 Microsoft.AspNetCore.*、EF Core、ABP、Avalonia、Serilog、CAP、Hangfire、Minio 等包版本。
- NuGet.config：仅保留官方 nuget.org 源，避免私有源干扰本地构建。
- common.props：统一 TargetFramework=net10.0、ImplicitUsings、Nullable、LangVersion=preview、Version=0.7.0、Authors/Company/Description/SatelliteResourceLanguages 等全局属性。

### 代码审查清单
- 架构一致性：是否遵循 ABP 分层与限界上下文划分。
- 包管理：是否通过 Directory.Packages.props 引入依赖，是否存在未集中管理的版本。
- 配置安全：连接字符串、密钥、远程服务地址是否在配置文件中管理，是否避免硬编码。
- 可测试性：是否提供接口抽象、是否注入依赖、是否可替换仓储与外部服务。
- 可维护性：是否添加必要注释、是否拆分复杂方法、是否避免深层嵌套条件。
- 性能：是否避免 N+1 查询、是否合理使用分页与投影、是否减少不必要的序列化。
- 前端：是否正确使用 IAppService 动态代理、是否正确配置懒加载、是否处理错误与空状态。
- 发布：是否更新版本号、是否记录变更、是否验证数据库迁移与部署脚本。

### 发布流程与版本管理策略
- 版本号：common.props 中统一 Version=0.7.0，发布时应提升该版本号并记录变更日志。
- 构建产物：Web 宿主与客户端分别构建；Release 模式启用 AOT 与裁剪以减少体积。
- 数据库迁移：发布前确保所有迁移已生成并经过测试；生产环境通过 DbMigrator 执行迁移。
- 部署：单体部署可直接发布 H.AppLab.Web.Host；微服务部署可按服务独立发布，并通过网关或反向代理组合。
- 回滚：数据库迁移需具备回滚方案；前端懒加载程序集需保证向后兼容。

## 性能考虑
- WebAssembly 懒加载：客户端仅在导航到对应路由时下载模块程序集与 pdb，显著降低首屏体积与启动时间。
- AOT 与裁剪：Release 模式启用 RunAOTCompilation，并对关键程序集设置 TrimmerRootAssembly，减少运行时代码体积。
- 数据库查询：避免 N+1 问题，合理分页、投影与缓存；对热点数据可使用 Redis。
- 异步与并发：后端尽量使用异步 IO，避免阻塞线程池；后台任务使用 Hangfire 或 Elsa 管理。
- 日志与监控：使用 Serilog 输出结构化日志，配合文件与控制台 Sink，必要时接入集中式日志系统。

## 故障排查指南
- 依赖服务无法连接：
  - 检查 docker-compose.yml 中 Redis/RabbitMQ/MinIO 端口与环境变量是否与应用程序配置一致。
  - 确认防火墙与 WSL 网络转发正常。
- 数据库迁移失败：
  - 检查连接字符串与 SQL Server 实例可用性。
  - 确认迁移文件顺序与回滚脚本正确。
- 前端懒加载程序集未加载：
  - 检查 H.AppLab.Web.Host.Client.csproj 中 BlazorWebAssemblyLazyLoad 列表是否包含新模块。
  - 查看浏览器 Network 面板是否有 404 或 CORS 错误。
- 桌面宿主无法调用后端：
  - 检查 appsettings.json 中 RemoteServices 的 BaseUrl 与 Http.AllowInvalidCertificates。
  - 确认后端 HTTPS 证书在本机被信任或允许无效证书。

## 结论
AppLab 是一个基于 .NET 10 与 Blazor 的模块化低代码平台，具备良好的分层架构、集中式包管理与前后端解耦能力。通过 Docker 编排依赖服务、DbMigrator 管理数据库、HttpClientProxy 简化前后端交互，开发者可以高效地扩展领域服务、设计页面并快速迭代。建议新加入者先从 README 与环境搭建入手，逐步熟悉低代码层与领域服务，再参与新功能开发与发布流程。
