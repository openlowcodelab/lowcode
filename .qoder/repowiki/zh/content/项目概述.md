## 引言
H.AppLab 是一个基于 .NET + Blazor + ABP Framework 的全栈企业级应用开发平台，同时具备低代码能力。其核心价值主张是：通过可视化设计器产出“应用元数据”，再由运行时渲染引擎根据元数据动态生成可运行的前端应用；后端则按限界上下文拆分为多个微服务，既支持单体部署，也支持按服务独立部署。

从仓库说明可知，该项目是应用开发实验性项目，采用模块化架构，宿主程序仅负责服务注册与组合，不直接承载业务逻辑。前端统一使用 Blazor Web App（Server + WebAssembly Client），并通过 IAppService 动态代理调用 HTTP API，从而让同一份契约在服务端与 WASM 客户端无感复用。

## 项目结构
整体仓库以 `src` 为根，按职责划分为宿主、组件、低代码核心、企业服务、系统应用、工具迁移和通用工具库等层次：

- **宿主层**：`Host`
  - 单体宿主 `H.AppLab.Web.Host` 聚合所有业务模块；另有单服务宿主如 `Account`、`RenderEngine`。
  - 宿主均为 Blazor Web App，包含服务端与 WebAssembly 客户端工程。
- **组件层**：`Components/AppDrawer`
  - 提供统一顶部导航、侧边菜单与应用抽屉的跨应用 UI 组件。
- **低代码层**：`LowCode`
  - `Common`：元数据 Schema、组件基类、默认组件库、实体与契约等公共基础。
  - `DesignEngine`：页面与组件的可视化设计器，产出应用元数据。
  - `RenderEngine`：根据元数据动态渲染应用；主题基于 Ant Design Blazor。
  - `meta`：应用与组件的 JSON 元数据示例目录。
- **服务层**：`Services`
  - 按领域划分的企业级微服务：Account、Organization、Approval、AI、Notification、Order、Portal、Setting、SupplyChain、BackgroundTask、Testing、File 等。
- **系统层**：`System`
  - Enterprise、SystemPortal 等面向平台运营的系统应用，与服务层隔离。
- **工具层**：`Tools`
  - 每个服务的 DbMigrator 控制台程序，用于初始化或更新数据库结构。
- **通用工具**：`Utils`
  - ABP 应用契约扩展、HTTP 动态代理、Blazor 工具、ID 生成器等。

## 架构总览
H.AppLab 采用“宿主 + 模块化服务 + 低代码引擎”的分层架构：

- **宿主层**：Blazor Web App 作为统一入口，聚合所有 Application 模块与 EF Core 基础设施。
- **服务层**：按领域拆分的微服务，遵循 Application.Contracts / Application / EntityFrameworkCore / Web 分层。
- **低代码层**：设计引擎与渲染引擎解耦，元数据贯穿两端。
- **客户端层**：WASM 客户端通过 IAppService 动态代理调用后端 API，按需懒加载程序集。

## 性能与运行时优化
- **Blazor Web App 模式**：服务端渲染与 WebAssembly 交互结合，兼顾首屏性能与交互能力。
- **响应压缩**：启用 Brotli 与 Gzip，并将 `.wasm`、`.dll` 加入压缩 MIME 类型，减少前端包体积。
- **WASM 懒加载**：仅在路由访问时加载所需程序集，降低初始下载量。
- **AOT 与裁剪**：Release 模式启用 AOT 与 Trimming，进一步减小客户端体积。
- **静态资源缓存**：通过指纹化 WASM 程序集并正确配置 boot manifest，避免旧清单导致的 404 问题。

## 快速开始指南
### 环境准备
- 安装 .NET SDK（版本见 `global.json`）。
- 安装 WSL + Docker（Engine + Compose）+ Portainer。
- 启动 Redis、RabbitMQ 等依赖服务：将 `cd/docker-compose.yml` 拷贝至 WSL 并运行 `docker-compose up -d`。

### 初始化数据库
- 使用 Tools 下的 DbMigrator 创建或更新数据库结构，例如：  
  `dotnet run --project src/Tools/H.Account.DbMigrator`

### 启动主程序
- 确保 Docker 已启动。
- 运行单体宿主：  
  `dotnet run --project src/Host/H.AppLab.Web.Host/H.AppLab.Web.Host --launch-profile HostAll`
- 默认访问地址为 `http://localhost:5045`（HTTPS 为 `https://localhost:7065`）。

### 首次运行建议
- 确认 `appsettings.json` 中连接字符串指向本地数据库。
- 检查 `RemoteServices` 是否指向正确的后端地址。
- 如需使用对象存储，请配置 MinIO 相关项。

## 故障排查要点
- **WASM 加载卡住**：可能是 boot manifest 与指纹化程序集缓存不一致导致。应避免对 `/_framework` 整个目录启用 immutable 长缓存，让框架自行处理清单校验。
- **远程服务不可达**：检查前后端 `RemoteServices` 配置是否一致，且目标服务已启动。
- **认证失败**：确认 Cookie 认证方案与登录页路径配置正确，外部登录开关与凭据是否正确。
- **多租户异常**：若租户 Cookie 失效，应清理无效租户 Cookie 并返回首页，而不是直接返回 404。
- **静态资源 404**：确保静态资源映射与压缩中间件顺序正确，并使用 `MapStaticAssets()`。

## 结论
H.AppLab 以 ABP 模块化架构为基础，结合 Blazor Web App 与低代码元数据驱动模式，提供了从可视化设计到运行时渲染的一体化解决方案。通过统一的宿主聚合、IAppService 动态代理、WASM 懒加载与多租户机制，平台既能满足企业级应用的复杂需求，又能显著降低重复开发与集成成本。对于初学者而言，理解“元数据—设计器—渲染器—微服务”的主干链路，是掌握该平台的关键。
