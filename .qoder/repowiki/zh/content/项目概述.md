## 简介
AppLab 是一个基于 .NET + Blazor 的实验性全栈应用开发平台。它同时承担两个角色：
- **业务应用运行时**：以 ABP Framework 为基础，提供账户、组织、审批、订单、供应链、通知、设置、背景任务等企业级服务。
- **低代码设计与渲染引擎**：通过元数据驱动页面和组件的设计、发布与运行，支持设计端可视化编辑与运行端动态渲染。

项目采用模块化架构，既支持单体部署，也支持按服务独立部署；前端主要使用 Blazor Web App，桌面端使用 Avalonia 作为本地宿主，整体围绕 ABP 的领域驱动分层与模块化约定组织代码。

## 项目结构
解决方案根位于 `src` 下，核心目录划分为以下七类：

## 核心组件
### 应用抽屉组件
AppDrawer 是跨应用的统一入口组件，负责顶部导航栏、侧边菜单与应用切换面板。它以元数据方式接入应用，通过分类信息与应用项配置图标、跳转地址和打开方式，使不同宿主只需提供应用和菜单数据即可复用一致的布局体验。

### 低代码元数据体系
LowCode.Common 提供元数据 Schema、组件基类、默认组件库以及实体与应用契约。DesignEngine 基于这些基础类型进行可视化设计，产出应用元数据；RenderEngine 则在运行时读取元数据并动态渲染出可运行的应用。元数据仓储支持 JsonFile、EntityFrameworkCore 和 RemoteService 多种实现，便于在本地、数据库或远程服务之间切换。

### HTTP 动态代理
前端通过 `H.Abp.HttpClientProxy` 直接调用服务端 `IAppService` 接口。该代理基于 `DispatchProxy` 拦截接口方法，按照 ABP 路由约定将方法名转换为 HTTP 请求，例如查询方法映射为 GET，新增方法映射为 POST，复杂参数自动序列化为请求体。同一套接口在服务端是进程内实现，在 WebAssembly 客户端则是 HTTP 代理，业务代码无感知。

## 架构总览
AppLab 的技术选型可以概括为：

| 层次 | 技术 | 作用 |
|---|---|---|
| 运行时框架 | ABP Framework | 提供模块化、领域驱动、应用服务、实体、EF Core、远程服务等基础设施 |
| Web 前端 | Blazor Web App | Server + WebAssembly Client 模式，兼顾实时交互与可部署性 |
| 桌面宿主 | Avalonia | 本地桌面应用宿主，承载工作区或设计相关界面 |
| 低代码内核 | 元数据驱动 | 设计端定义元数据，运行端解析元数据渲染页面与组件 |
| 数据持久化 | SQL Server + EF Core | 各服务通过 EntityFrameworkCore 管理数据库表结构 |
| 缓存与消息 | Redis + RabbitMQ | Redis 用于缓存与会话，RabbitMQ 用于异步消息与背景任务 |
| 对象存储 | MinIO | 提供兼容 S3 的对象存储服务，用于文件上传与静态资源托管 |

### 启动步骤
1. **准备依赖服务**  
   将 `cd/docker-compose.yml` 复制到 WSL 中并执行 `sudo docker-compose up -d`，启动 Redis、RabbitMQ、MinIO。

2. **执行数据库迁移**  
   运行对应服务的 DbMigrator，例如账户服务迁移命令为 `dotnet run --project src/Tools/H.Account.DbMigrator`。其他服务类似，替换为对应的 Tools 项目路径。

3. **启动主程序**  
   启动单体宿主 `H.AppLab.Host.All`：
   ```text
   dotnet run --project src/Host/H.AppLab.Host.All/H.AppLab.Host.All --launch-profile HostAll
   ```
   默认访问地址为 `http://localhost:5045`，HTTPS 默认端口为 `7065`。

## 性能与运行特性
- **WebAssembly 懒加载**：首页仅加载必要程序集，其余 Contracts、LowCode 库及第三方依赖在导航到对应路由时才按需下载，减少首屏体积。
- **自研组合式依赖注入**：LazyModuleRegistry 管理各路由模块的服务容器，CompositeServiceProvider 提供“根容器 → 模块容器”的服务解析回退，支持程序集加载后延迟注册服务。
- **发布优化**：Release 模式启用 AOT 与裁剪，进一步减小下载体积；Debug 模式额外加载 `.pdb` 以便调试。
- **HTTP 动态代理**：前端无需手写 HttpClient 调用，降低样板代码量并保持一致的远端调用语义。

## 常见问题排查
| 现象 | 可能原因 | 处理建议 |
|---|---|---|
| 无法连接 Redis | Redis 未启动或密码不一致 | 检查 `docker-compose.yml` 中 Redis 是否运行，确认连接字符串与密码配置一致 |
| 消息队列不可用 | RabbitMQ 未启动或端口被占用 | 检查 RabbitMQ 容器状态、5672 与 15672 端口，必要时清理残留容器 |
| 文件上传失败 | MinIO 未启动或凭据错误 | 检查 MinIO 容器、API 端口 9010 与控制台 9011，确认 AccessKey 与 SecretKey |
| 数据库迁移失败 | 连接字符串错误或数据库权限不足 | 检查各 DbMigrator 的 `appsettings.json` 连接字符串，确认 SQL Server 可访问 |
| 前端页面空白或路由失效 | 懒加载程序集未正确加载 | 检查 WebAssembly 客户端路由与 `BlazorWebAssemblyLazyLoad` 配置 |

## 结论
AppLab 以 ABP Framework 和 Blazor 为核心，构建了一个既能承载企业级业务应用，又能支撑低代码设计与渲染的平台型解决方案。其模块化目录结构清晰区分了宿主、共享组件、低代码核心、企业服务、系统应用、迁移工具与通用工具，有利于团队分工、独立部署和持续演进。对于初学者，可以从 Host 与 README 的快速开始入手；对于有经验的开发者，LowCode 的元数据体系、Services 的分层约定、Tools 的迁移策略以及 Utils 的动态代理都是值得深入研究的工程实践点。
